## 3. 网页功能操作地图（点什么 → 得到什么）

### 仪表盘区
- **打开首页** → 顶部三张 ROI 卡（省时/省人力/机器耗时）+ 分类分布 + 缺陷分布
- 这些数字与提交产物**同源**，不是装饰

### 审计队列（主表格，520 封）
- **按状态筛选** OK / MISMATCH / NEEDS_REVIEW → 只看对应邮件
- **按类别筛选** BL_COMPARISON / SI_REQUEST / INVOICE_QUERY / GENERAL / SPAM
- **搜索框**输入 ID / 主题 / 发件人关键词 → 模糊过滤
- **只看缺陷**开关 → 快速定位 46 封 MISMATCH
- **点任意行** → 右侧/下方打开详情

### 邮件详情
- **七字段对照表**：Shipper / Consignee / Notify Party / Port of Loading / Port of
  Discharge / Container Count / Gross Weight——红=不一致、黄=待人审、绿=一致
- 云端模式下字段格显示 "No comparable SI / draft-BL fields…" 占位（服务器没有附件
  字节，结论来自归档；本地跑 `make bootstrap` 后有完整对照）
- **改判操作**：选状态 → 勾缺陷字段 → 填备注/审核人 → 提交 → 行上出现改判徽章，
  提交预览实时更新；**Revert** 可撤销

### 实时拉取（Live Pull）
- **点一次按钮** → 取下一批（默认 6 封，池子共 126 封可比对邮件，环状轮转）
- 每封显示：分类 → 结论 → 缺陷字段 → 四步 Agent 轨迹（可展开看每步耗时/依据）
- 通道徽章：`deterministic`（本地毫秒级）/ `cloud-replay`（线上回放归档结论）/
  `gemini`（本地开了多模态开关时）

### 上传核对（Upload & Verify，核心交互）
- **上传 SI + BL 两个文件**（txt/pdf/docx）→ 点 Verify → 等几秒
- 得到：分类+置信度 → 双侧字段抽取 → 七字段红绿对照 → 最终裁决 → 可展开的 Agent
  轨迹
- 上传记录存 `upload_runs` 表，与官方 520 封评测数据**严格隔离**

### 提交预览（Submission）
- 显示官方 5 键产物：恰好 520 条，每条只有 category/status/review_reason/has_defect/
  defect_fields
- `problems: []` = 合约干净；这里的产物就是官方打分器要打分的东西

## 4. 关于「AI 是不是只有 VS Code 才能用」——不是！

| 场景 | AI（Gemini）可用吗 | 原因 |
|---|---|---|
| 公网 Vercel 页面 | ✅ **可用** | 你的 Gemini key 配在 **Railway 后端**的变量里，AI 在服务器端被调用。任何浏览器访问都能获得完整 AI 能力 |
| 本地开发 | ✅ 可用 | key 在本地 `.env` 里，后端进程读它 |
| key 会不会泄露到公网 | ❌ 不会 | 前端零密钥（BFF 架构）：浏览器只跟你的 API 说话，key 永远不出后端进程 |

**一句话**：VS Code 只是你写代码的地方，不是 AI 的开关；Vercel 公网页面走的是
后端代理，AI 能力完整，且密钥绝对安全。

唯一区别：公网「实时拉取」为了保护 520 键提交产物走 `cloud-replay`（回放归档结论，
毫秒级、不花钱不写库）；本地开了 `use_llm` 才会现场调 Gemini 重跑管线（2-14 秒/封，
花 token）。上传核对面板在公网**照常真调 AI**。

## 5. 红色日志怎么看（Railway Deploy Logs）

- **部署窗口期**（换容器那 1-2 分钟）出现零星 502 是正常现象
- `INFO: ... 200 OK` 是正常访问日志
- 需要警惕的是**持续出现**的 `ERROR: Exception in ASGI application` +
  具体异常名。今后异常消息全部是英文，`detail` 会直接告诉你原因
  （比如列名错、连接失败、数据缺失），照着修即可
- 历史红色日志（9 月 24 日 12:54 之前那批 `column emails.status` / `InboxError`）
  属于已修复版本，看最新时间戳即可
